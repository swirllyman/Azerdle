# Azerdle

A World of Warcraft: **Forever** addon: a daily Azeroth-themed Wordle (same word for everyone each day, picked from
the server date) with guild, friends and global leaderboards. There is no server, so leaderboards are
peer-to-peer over hidden addon messages. The project folder is still called `AzerothWordle` (the working title);
everything inside the addon is `Azerdle`, and `/azerdle` (short `/azd`) is its slash command.

**Naming:** the addon was released as "Word of Warcraft" (v0.1.x betas, prefix `WoWordProbe`, SavedVariables
`WordOfWarcraftDB`) and renamed to Azerdle after CurseForge flagged the name as too close to the trademark. Keep
"Warcraft", "WoW" and "Wordle" out of the addon's name, title and slash command.

## Forever restrictions (the modern Midnight-era client)

- Many values are **secret** to addon code: they can be displayed but not compared, indexed or used in math.
  Guard anything that might be secret with `ns.isSecret()` (wraps `issecretvalue`) before comparing or indexing.
  Retail Midnight also makes some chat content secret, so received sender names may be too.
- Some APIs raise a "blocked action" popup even under `pcall` (e.g. registering `COMBAT_LOG_EVENT_UNFILTERED`).
- Midnight restricts addon comms in instances during encounters / M+ / rated PvP. Whether Forever does is one of
  the probe's questions.
- Players have two names. Verified from login snapshots (2026-09-28, nothing here is secret): `UnitName("player")`
  returns `"Bear", "Joegre"`, i.e. the surname sits in the **realm slot**; `GetUnitName(unit, true)` and
  `GetPlayerInfoByGUID` give `"Bear Joegre"` (space, realm return empty); WTF character folders are `Bear-Joegre`.
  The real realm only comes from `GetRealmName()` ("Classic Beta PvE 2") / `GetNormalizedRealmName()`. Which form
  addon whispers are addressed to, and what CHAT_MSG_ADDON reports as sender, is still unverified (no two-player
  run yet). Identify players by GUID, not by name strings.
- Forever-specific APIs found by `/azerdle probe` API discovery (2026-09-28): `C_NameUtil.ReplaceSurnameSeparatorWithLinkSeparator`
  (full name → link/addressing form, probably `Bear-Joegre`), `C_PlayerInfo.ShouldDisplaySurname`,
  `C_ChatInfo.AreOutgoingAddonChatMessagesRestricted` and `C_ChatInfo.InChatMessagingLockdown` (check before
  sending), `C_BattleNet.SendGameData` next to `BNSendGameData`. Battle.net reports Forever characters as
  `wowProjectID = 18` even though the `WOW_PROJECT_ID` global is 1: match BN friends on 18.
  `GetServerTime()` is UTC epoch seconds.
- The hidden custom channel joins fine (`JoinTemporaryChannel`), but its number varies (1, 6, 7): always look it up
  with `GetChannelName(name)` before sending.
- Lua 5.1, max 200 locals per function scope (including a file's top level): split features into files that
  share the addon namespace (`local _, ns = ...`).
- Addon messages: 255 bytes, prefix ≤ 16 chars, throttled (burst of ~10, then ~1/sec).

## The game

- **Daily word:** puzzle n is the UTC day `floor((GetServerTime() - ns.EPOCH) / 86400) + 1` (#1 = 2026-09-28), so
  time zones and realm clocks can't split players; new word at 00:00 UTC. Word = `ns.ANSWERS[n]`, wrapping only
  after the list runs out.
- **Answers are append-only and in daily order.** Add words to `tools/data/answers.txt` and run
  `python tools/build_words.py`: existing order is kept and new words are appended shuffled (fixed seed). Never
  reorder or remove; replacing a word by hand in Words.lua is only safe if its day hasn't come. 229 answers at
  launch (runs out around May 2027), so add more before then. Words.lua is readable, so a curious player can
  spoil future days; accepted, it's a casual game.
- **Word length 5** (see `tools/data/length_analysis.md`). Curation bar: well known to a Classic player, WoW
  meaning obvious, no simple -S plurals, no spoilers or offensive words, no filler like APPLE/ERROR.
- **Guesses:** answers + lore_guesses + English words from wordfreq with Zipf >= 2.0 (~10.4k), minus the
  blocklist. wordfreq's data is CC BY-SA 4.0: keep the credit in Words.lua's header.
- **Scoring:** greens first, then each remaining answer letter turns at most one guessed letter yellow, left to
  right.
- **Stats** per character: a puzzle counts once; a win continues the streak only if the previous puzzle was won;
  `ns.currentStreak` shows a streak as broken once a day is missed. Practice games never touch stats.
- **Saving:** today's guesses are saved after each guess and replayed on load (replay skips the word-list check,
  so a list update can't drop a saved guess, and doesn't fire `ns.onGameFinished` again).
- **Typing:** an invisible EditBox takes focus while the window is open (works in combat, no protected calls).
  That also captures movement keys; Esc closes the window.
- **Options** are account-wide in `AzerdleDB.options`; only values that differ from the default are stored.
  Add one by adding a `SPEC` entry in Options.lua (the panel, Settings page and `/azerdle set` follow), read it with
  `ns.opt`, and if changing it must redraw something, add an `OPTION_APPLY` entry in UI.lua.
- **Hard mode** (Wordle's rules): fixed on a game at its first guess (`game.hard`), saved with today's game, adds
  `*` to the share header. Switching it on mid-game waits for the next game; switching it off applies at once.
- **Sharing:** "Copy result" shows an emoji grid in a read-only copy box (emoji may draw as boxes in WoW but copy
  fine). "Post to chat" sends one line with raid-icon squares (`{rt4}` green, `{rt1}` yellow, `{rt5}` grey) to
  GUILD, else PARTY, never SAY; unverified that raid icons render in guild chat on Forever.

## The probe (`/azerdle probe`)

Prefix `AzerdleProbe`, hidden channel `AzerdleProbe` (joined 5s after login, removed from chat frames, join
notices filtered). Every client with the addon **answers pings automatically**; only one player has to type.

- `/azerdle probe`: full run. Logs identity (UnitName, UnitFullName, GetUnitName, UnitPVPName, GUID,
  GetPlayerInfoByGUID, Ambiguate forms, BN info), time APIs, API discovery (function lists of C_ChatInfo,
  C_FriendList, C_BattleNet, C_GuildInfo, C_Club, C_PlayerInfo…, plus any global/C_ API with Surname / FirstName /
  DisplayName / Nickname / FullName in its name), character + Battle.net friends, guild roster (first 15), then a
  ping round.
- Ping round: `PING;round;how;guid;name;surname;realm;serverTime` on GUILD, CHANNEL, PARTY/RAID, INSTANCE_CHAT and via
  `BNSendGameData` to every Battle.net friend online in WoW. Each send's pcall result and
  `Enum.SendAddonMessageResult` is logged with context (combat, instance, encounter, chat lockdown).
- A receiver logs every CHAT_MSG_ADDON arg with secrecy, then answers: `ACK` whispered to the exact sender
  string; `ACKB` on the same broadcast distribution (so the pinger learns how it was seen even if whispers fail);
  once per pinger per round, `WV` whispers addressed by every name form it can build (raw sender, Ambiguate
  none/short, first name, `First-Surname`, `First Surname`, `First-Realm`, `First Surname-Realm`,
  GetPlayerInfoByGUID name). Identical strings are sent once with merged labels (`sender+Name-Surname`). The
  pinger's log shows which forms arrived. System messages right after a whisper ("No player named …") are logged.
- `/azerdle probe target`: whisper-pings the targeted player under each name form. `/azerdle probe whisper <name>`: one
  typed name. `/azerdle probe auto`: ping every 60s, on combat start, boss pull and zoning (persists across reloads).
  `/azerdle probe note <text>`: annotate the log. `/azerdle probe status`.
- Sender fields (never text) of ordinary chat events (whisper, guild, party, say, BN whisper) are logged, up to 30
  per session, to compare with CHAT_MSG_ADDON's sender.

## Releasing

GitHub: `swirllyman/Azerdle` (branch `main`; was `Word-Of-Warcraft`, which redirects). CurseForge project 1718001. Pushing a `v*` tag runs
`.github/workflows/release.yml` (BigWigs packager), which builds the zip per `.pkgmeta`, uploads it to CurseForge
(project ID from `## X-Curse-Project-ID` in the .toc, token from the `CF_API_KEY` repo secret) and creates a GitHub
release. `alpha`/`beta` in the tag name gives that release type. No CurseForge webhook: it never produced a file.
Check a run with `gh run view <id> --log` ("Uploading ... to https://azerdle.curseforge.com/..." then "Success!").

## Working on it

- **Game install:** `C:\Program Files (x86)\World of Warcraft\_classic_beta_\`. `Interface\AddOns\Azerdle`
  is a **junction** to this project's `Azerdle/`, so edits are live. `/reload` picks up Lua changes; new
  files (textures, new .lua/.toc entries) need a full client restart.
- **Log:** `AzerdleDB.log`, written on reload/logout to
  `…\_classic_beta_\WTF\Account\<account>\SavedVariables\Azerdle.lua`. Reading it after the user plays is
  the main debugging loop. `/azerdle log [n]` shows recent lines, `/azerdle echo` echoes every line to chat.
- **Tests:** no Lua install. `pip install lupa luaparser`, then run `python tools/test_game.py`,
  `python tools/test_ui.py` and `python tools/test_probe.py`. `luaparser` works as a syntax check. The fake
  raises "Font not set" like the real client when a FontString/EditBox gets text before a font; it doesn't
  check layout, templates or anything visual. `lupa` runs Lua 5.5: `table.maxn`/`unpack` are shimmed in the fake, but don't rely on 5.2+
  features in addon code.
- **Gotchas:**
  - Bash heredocs in this environment collapse backslashes, which silently breaks texture paths like
    `"Interface\\Buttons\\WHITE8X8"`. Edit Lua with the file tools, and grep `Interface` after scripted edits.
  - Never use a possibly secret value as a table key, in `==`/`<`, or in `..`: use `ns.show()`.
  - `GetServerTime()` is an integer; `date()` rejects fractional times.
  - FontStrings and EditBoxes need `SetFont`/`SetFontObject` before `SetText`, or the client errors.
  - Templates (`BackdropTemplate` etc.) may differ on Forever: create frames through UI.lua's `newFrame`, which
    falls back to a plain frame.
